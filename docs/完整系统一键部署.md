# FusionWeb 完整系统一键部署

本文档说明如何把 FusionWeb 发布到阿里云容器镜像服务 ACR（杭州区），以及用户克隆 GitHub 仓库后如何通过一个脚本启动完整系统。

## 1. 发布架构

生产环境固定包含六个 Linux 容器：

| 服务 | ACR 仓库 | 标签 |
|---|---|---|
| API | `fusionweb-api` | `${VERSION}`、`latest` |
| Web | `fusionweb-web` | `${VERSION}`、`latest` |
| 默认 Worker | `fusionweb-worker` | `${VERSION}`、`latest` |
| PostgreSQL | `fusionweb-postgres` | `17-alpine` |
| Redis | `fusionweb-redis` | `7.4-alpine` |
| MinIO | `fusionweb-minio` | `RELEASE.2025-07-23T15-54-02Z` |

所有发布镜像目标平台均为 `linux/amd64`。Windows 部署依赖 Docker Desktop 的 Linux Containers。

镜像公共前缀：

```text
crpi-bw40e2qu21b597zs.cn-hangzhou.personal.cr.aliyuncs.com/fusionweb/fusionweb
```

项目当前 `VERSION` 为 `0.1.0`。

## 2. 一次性准备 GitHub 仓库

1. 创建公开 GitHub 仓库，建议名称 `FusionWeb`，默认分支 `main`。
2. 在项目目录执行：

```bash
git init
git branch -M main
git add .
git commit -m "Initial FusionWeb release"
git remote add origin https://github.com/<owner>/FusionWeb.git
git push -u origin main
```

`.gitignore` 已排除 `.env`，不得强制提交任何数据库密码、Redis 密码、MinIO 密钥、JWT、Basic Auth 密码或 Worker Key。

## 3. 一次性准备阿里云 ACR

地域选择 **华东 1（杭州）**。

1. 创建一个 ACR 命名空间。
2. 在该命名空间创建六个仓库：

```text
fusionweb-api
fusionweb-web
fusionweb-worker
fusionweb-postgres
fusionweb-redis
fusionweb-minio
```

3. 将六个仓库都配置为公开拉取。
4. 不要把 ACR 密码写入代码、`.env.example`、Dockerfile 或 Compose。

## 4. 配置 GitHub Actions

在 GitHub 仓库的 **Settings → Secrets and variables → Actions** 中设置：

### Secrets

```text
ALIYUN_REGISTRY_USERNAME
ALIYUN_REGISTRY_PASSWORD
```

### Variable

```text
ALIYUN_REGISTRY_NAMESPACE
```

`ALIYUN_REGISTRY_NAMESPACE` 只填写命名空间名称，不填写 Registry 主机名。

工作流 `.github/workflows/docker-images.yml` 会：

1. 从根目录 `VERSION` 读取版本；
2. 校验 ACR Variable 和 Secrets 已配置；
3. 使用 Buildx 构建 API、Web、Worker 的 `linux/amd64` 镜像；
4. 使用 GitHub Actions Cache 缓存业务构建层和 Worker 扫描工具构建层；
5. 推送固定版本标签和 `latest`；
6. 使用 `skopeo` 把固定版本 PostgreSQL、Redis、MinIO 同步到 ACR；
7. 当触发源是 `v*` Git Tag 时，要求 Tag 去掉 `v` 后与 `VERSION` 完全一致。

## 5. 首次发布镜像

完成 ACR 和 GitHub 配置后，可以：

- 推送到 `main` 自动发布；或
- 在 GitHub Actions 中手动运行 `Build and publish FusionWeb images`。

正式发布 Tag 示例：

```bash
git tag v0.1.0
git push origin v0.1.0
```

如果 Tag 为 `v0.1.1`、而 `VERSION` 仍为 `0.1.0`，工作流会立即失败，防止错版。

发布完成后，需验证六个仓库的 Manifest 可匿名读取，并确认 API/Web/Worker 的 `0.1.0` 与 `latest` 来自同一次工作流。

## 6. 仓库默认 ACR 前缀

当前仓库已按阿里云 ACR 杭州区命名空间 `fusionweb` 写入默认镜像前缀：

```text
crpi-bw40e2qu21b597zs.cn-hangzhou.personal.cr.aliyuncs.com/fusionweb/fusionweb
```

已同步的位置：

- `.env.example`；
- `docker-compose-worker.yaml` 的默认前缀；
- `api/worker_handler.go` 的远程 Worker 镜像 fallback；
- 文档示例与报告。

如果未来更换 ACR 命名空间，只需统一替换 `crpi-bw40e2qu21b597zs.cn-hangzhou.personal.cr.aliyuncs.com/fusionweb/fusionweb`，然后重新触发 GitHub Actions 发布镜像。

生产主 Compose 会把 `FUSIONWEB_IMAGE_PREFIX` 注入 API，因此前端“节点管理”正常情况下会显示真实 Worker 镜像。

## 7. Linux 一键安装

支持 Docker Engine 和 Docker Compose v2。若未安装 Docker，脚本会先询问是否使用 Docker 官方脚本安装。

```bash
git clone https://github.com/<owner>/FusionWeb.git
cd FusionWeb
chmod +x fusionweb.sh
./fusionweb.sh install
```

`install` 会：

- 检查 Docker 和 Compose；
- 从 `.env.example` 创建 `.env`（已有 `.env` 不覆盖）；
- 从 `VERSION` 写入 `FUSIONWEB_VERSION`；
- 为 PostgreSQL、Redis、MinIO、JWT、Basic Auth、Worker Key 生成安全随机值；
- 校验 Compose；
- 拉取六个公开 ACR 镜像；
- 执行 `up -d --wait` 并检查六个容器。

访问地址：

```text
HTTP  http://localhost:8756
HTTPS https://localhost:8988
```

HTTP 会跳转到 HTTPS。HTTPS 使用自动生成的自签证书。

查看 Basic Auth 密码：

```bash
grep '^FUSIONWEB_BASIC_PASS=' .env
```

## 8. Windows 一键安装

要求：

- Windows 10/11 或 Windows Server 上可用的 Docker Desktop；
- Docker Desktop 已切换到 **Linux Containers**；
- Docker Compose v2 可用；
- 发布镜像平台为 `linux/amd64`。

```bat
git clone https://github.com/<owner>/FusionWeb.git
cd FusionWeb
fusionweb.bat install
```

BAT 会调用系统 PowerShell 的加密随机数生成器创建安全密钥，但不会创建或依赖独立 PowerShell 部署脚本。

查看 Basic Auth 密码：

```bat
findstr /B "FUSIONWEB_BASIC_PASS=" .env
```

## 10. 升级

```bash
./fusionweb.sh check-update
./fusionweb.sh upgrade
```

或：

```bat
fusionweb.bat check-update
fusionweb.bat upgrade
```

升级流程：

1. 拒绝在有未提交修改的 Git 工作区中升级；
2. 执行 `git pull --ff-only`；
3. 读取新 `VERSION`；
4. 只更新 `.env` 中的 `FUSIONWEB_VERSION`；
5. 拉取镜像并重建容器；
6. 保留所有数据卷；
7. 失败时把 `.env` 版本恢复成旧版本并打印回滚命令。

## 11. 固定版本与回滚

如需固定到已发布版本，编辑 `.env`：

```env
FUSIONWEB_VERSION=0.1.0
```

然后执行：

```bash
./fusionweb.sh start
```

或：

```bat
fusionweb.bat start
```

`start` 不执行 `down -v`，因此 PostgreSQL、Redis、MinIO 和应用数据不会被删除。

## 12. 默认 Worker 与远程 Worker

主 `docker-compose.yaml` 会始终启动 `fusionweb-worker` 默认 Worker。API 设置 `FUSIONWEB_LOCAL_CONSUMER=false`，扫描任务由 Worker 从 Redis 队列消费，不应长期停留在“等待中”。

远程 Worker 需要直接访问 PostgreSQL、Redis 和 MinIO。仅在确需远程节点时叠加：

```bash
docker compose -f docker-compose.yaml -f docker-compose.remote-access.yaml --env-file .env up -d
```

并在 `.env` 设置：

```text
FUSIONWEB_WORKER_EXTERNAL_PG_DSN
FUSIONWEB_WORKER_EXTERNAL_REDIS_ADDR
FUSIONWEB_WORKER_EXTERNAL_MINIO_ENDPOINT
```

完成后重启 API。前端“节点管理”会生成包含真实 ACR Worker 镜像、Worker Key 和远程连接参数的 Linux/Windows 命令。生成的命令会先 `docker compose pull`，再启动并等待 Worker。

基础设施端口优先绑定 VPN 或内网地址，不建议直接绑定公网地址。

## 13. 卸载

```bash
./fusionweb.sh uninstall
```

或：

```bat
fusionweb.bat uninstall
```

脚本会明确提示以下数据将永久删除，并要求输入 `DELETE`：

- PostgreSQL 数据卷；
- Redis 数据卷；
- MinIO 对象数据卷；
- 应用数据卷；
- 自动生成密钥卷；
- 自签证书卷。

确认后执行等价于：

```text
docker compose down -v --remove-orphans
```

源码目录、`VERSION` 和 `.env` 会保留。

## 14. 开发模式

生产 `docker-compose.yaml` 只包含 `image:`，不现场构建业务镜像。

开发时才叠加源码构建覆盖层：

```bash
docker compose -f docker-compose.yaml -f docker-compose.dev.yaml --env-file .env up -d --build
```

Worker 镜像包含多个扫描工具，完整源码构建耗时可能较长。正式镜像构建应由 GitHub Actions 完成。

## 15. 发布前检查清单

- [ ] 已创建公开 GitHub 仓库并推送 `main`；
- [ ] 已创建 ACR 杭州命名空间；
- [ ] 六个 ACR 仓库已创建并设为公开；
- [ ] 两个 GitHub Secrets 和一个 Variable 已配置；
- [ ] `.env.example` 中占位命名空间已替换；
- [ ] GitHub Actions 成功发布六个镜像；
- [ ] 六个 Manifest 可匿名读取；
- [ ] Linux 全新机器只运行 `fusionweb.sh install` 即可启动；
- [ ] Windows 全新机器只运行 `fusionweb.bat install` 即可启动；
- [ ] 创建扫描任务后默认 Worker 能消费；
- [ ] 节点管理能看到默认 Worker 并生成远程命令；
- [ ] 固定版本回滚不删除数据；
- [ ] `uninstall` 确认后删除全部数据卷。
